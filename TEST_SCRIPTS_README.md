# Validation

Use Node 24 and the checked-in npm lock. Python 3, Bash and PowerShell are required to exercise every regression suite without skips. Terraform 1.9.8 and the checked-in provider lock qualify configuration syntax/resources separately.

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm test
node --test tests/*.test.js
npm run test:all --workspace=webhook-handler -- --runInBand
npm test --workspace=cleanup-function -- --runInBand
npm run test:python
npm run check:archive
npm run check:dependencies
terraform -chdir=terraform fmt -check -recursive
terraform -chdir=terraform init -backend=false -input=false -lockfile=readonly
terraform -chdir=terraform validate -no-color
terraform -chdir=terraform test -no-color
```

`npm test` runs the complete built-in Node suite, full webhook and cleanup Jest suites, and `scripts/test-python.py`, which discovers every Python regression directory and fails if any test is skipped. The [CI workflow](.github/workflows/ci.yml) uses the same complete regression scope. It also checks JavaScript/Python/Bash and PowerShell syntax, uses read-only repository permissions and performs no cloud deployment, Pages publication or provider inference.

The built-in Node suites cover controller composition, durable allocation/recovery, bootstrap identity, actual-job association, invocation authentication, retirement, worker control and archive closure. Workspace Jest suites cover webhook and cleanup source. Python covers embedded provisioner, setup tooling, lifecycle helpers and worker behavior with controlled synthetic clients.

Coverage reports are generated locally and ignored:

```sh
npm run test:coverage
npm run test:coverage-check
```

The root coverage collector combines production JavaScript evidence across the fixture and framework test contexts. `npm run test:coverage-check` enforces at least **81% per production JavaScript file** for lines, branches, functions and statements; it includes unexecuted production files so omissions cannot silently improve the percentage. This implements the historical over-80% JavaScript criterion. The gate is a requirement, not a claim that a particular commit passed it: retain the exact final command/report as evidence and resolve any failing files. Python/shell regressions are exercised by the test runner, but no Python/shell coverage percentage or live deployment coverage is claimed. Narrow workspace coverage commands remain diagnostics; they do not replace the root gate.

Qualification evidence should include the exact commit/tree, tool versions, dependency/provider lock hashes, commands, totals, skips and failures. Keep logs free of secret values and private operational identifiers. Regenerate the path ledger after adding/removing a replacement so it cannot silently claim parity for absent files.

`npm run check:archive` is read-only and fails with `ARCHIVE_INVENTORY_STALE` if the current source, deployment lock, declared imports, source mapping or file modes differ from the tracked contracts. After an intended source change, inspect the differences, run `node packaging/check-controller.js --write-inventory`, and review/commit the resulting `deployment/archive-manifest.json`, `deployment/declared-imports.json` and `deployment/archive-source-map.json` changes. Regeneration does not qualify a revision and refuses invalid closure or unsafe modes. Historical source-only manifests and unresolved fixtures are retained separately and are never regenerated by this command.

After committing, run `npm run package:controller -- dist/<fresh-run>/controller` into a fresh destination. It produces and physically verifies the ZIP, then writes `controller-receipt.json` alongside it, binding the clean commit/tree, tool versions, tool and lock hashes, tracked inventories, archive SHA/count and completed packaging commands. It refuses existing companion outputs and a dirty or changing revision. The receipt has **packaging-only scope**; it does not claim a full test run, independent dependency installation or live qualification. Keep the full source/hosted logs and their exact head identity with it. `deployment/offline-qualification.json` is an explicitly historical observation with unknown original revision/time, not a current contract. Dated observations in `deployment/gaps.json` likewise apply only to their named commit.

Live acceptance requires separately authorized cloud resources and a disposable trusted-repository job. Green source checks cannot establish effective IAM, image provenance, private networking, SDK service behavior, JIT expiry, lifecycle latency or safe retirement of real workers.

The separate source-compatible workflow uses read-only hosted validation and an isolated offline fixture tree. Only its successful main-push publisher has `contents: write`; PR reports are never promoted. Endpoint tests invoke all four PowerShell scripts through their real parameters with request stubs. Workflow regressions parse job policy and verify hostile PR titles remain shell data. Materialization tests check explicit purpose, notice integrity and non-executable reference output. The [dependency assessment](docs/DEPENDENCIES.md) records dated advisory/exposure observations separately from generated lock facts; source tests do not assert all advisories are remediated.

Runtime ownership checks require exact root/standalone dependency parity, Node 24/CommonJS and workspace test-context subsets. `node scripts/dependency-inventory.cjs --write` deliberately refreshes the four-lock source inventory after reviewed changes; check mode is offline/read-only. Refresh authored assessments when lock hashes change. `python3 scripts/qualify-source-profile.py` independently installs the supported standalone package outside repository ancestors before its two reference installs. The SDK/framework/disabled-route checks cannot borrow root modules and use no provider operations.
