# Compatibility and supported profiles

The root implementation is the supported trusted-private one-job Spot VM deployment. Public PR validation belongs on GitHub-hosted runners. The compatibility templates are retained for readable reference and isolated offline regression qualification; they are not an alternate deployment path.

| Capability | Supported implementation | Acceptance boundary |
| --- | --- | --- |
| Configuration and deployment | Root Terraform and `scripts/setup*` / `sync-terraform-config*` | Operator supplies identities, immutable images and numbered secret references; local setup does not deploy. |
| Signed scaling and capacity | Raw-byte HMAC, configured numeric repository identity, current private-repository authorization, routing labels and transactional allocation | Public/unproven new demand is rejected before reservations/build submission; waiting replay revalidates current authority. |
| Worker startup and retirement | Allocation-bound App JIT, one unprivileged runner per private VM, controller-owned exact retirement | No management credentials on workers; live IAM/image/JIT/network/lifecycle evidence remains necessary. |
| Contributor validation | Hosted read-only CI, complete regression scope, 81% per-file JavaScript coverage and mocked Terraform tests | Source evidence does not establish a successful deployment or hostile-workload isolation. |
| Optional review automation | [Checked-in caller](../.github/workflows/review-sensei-review.yml) and [configuration](../.reviewsensei.yml) | Maintainer tooling independent of controller deployment. |
| Compatibility templates | `source-compatible/manifest.json` and reference materializer | Non-executable CLI outputs; explicit internal offline-qualification mode retains executable fixtures. No supported legacy operator deployment. |

The [path ledger](migration-map.json) records retained paths, replacements and exclusions. The [behavior matrix](../source-compatible/behavior-matrix.json) distinguishes template integrity, adaptations and inherited defects. Endpoint validation, safe hosted examples, license metadata and reference-only materialization are deliberate adaptations; unchanged-file counts do not describe the final security boundary.

Worker-image builds now use the [allowlisted local source stage](WORKER_IMAGE.md) instead of submitting the repository root. Run `python3 packaging/worker-image-source.py stage --output dist/worker-image-source` and verify that stage before using the updated build command. Existing stages are never overwritten. This repairs omitted Packer/bake/runner inputs without relaxing the root ignore policy or changing image/runtime versions, IAM or deployment settings. The previous root upload is not a supported fallback; reverting the packaging change requires withholding image builds until their source closure is corrected.

Controller packaging now checks tracked inventory drift before assembly and records a clean revision-bound local packaging receipt. Intentional source/lock/path/mode changes require explicit `node packaging/check-controller.js --write-inventory`, review and commit before `npm run package:controller -- dist/<fresh-run>/controller`. Use the verified ZIP directly; never re-ZIP the stage manually. Existing companion outputs are preserved by refusal, and historical run records/unresolved fixtures remain historical. Revert the inventory/check/receipt changes together if rolling back; no deployed runtime or state format changes are involved.

Each retained template has a current digest. Existing historical source-digest fields remain evidence, while new project helpers are identified as adaptations. Root MIT license and notice bytes are included in generated distributions. No third-party dependency is relicensed by the project notice.

Old materialized directories are not rewritten. Regenerate a reference with `--purpose reference`; use the root supported route for deployment. Historical waiting-demand records lacking the required numeric repository/private context remain preserved and ineligible for new provisioning until an operator reconciles them. Drain a live workload deployment before changing its repository visibility; uncertain resources are never deleted just to satisfy a transition.

Current-file endpoint removal does not erase Git history or cached PR content. Publication review must inspect those surfaces separately. The [dated dependency assessment](DEPENDENCIES.md) replaces stale numeric alert prose; it distinguishes current lock facts from advisory observations and does not provide blanket security clearance.

The root runtime dependency declaration is canonical; standalone deployment keeps its own matching production lock, while private CommonJS workspaces remain test/compatibility contexts. Archive checks now reject declaration/engine/module drift, and source qualification independently installs the standalone closure outside the repository before the reference closures. Review and regenerate `deployment/dependency-inventory.json` after intentional lock changes, then refresh its separately authored assessment. No dependency versions change in this inventory milestone.

The management CLI now prints the controller-reported status and a fixed explanation instead of a generic operation confirmation. Update any consumers of its human-readable stdout. With `--execute`, exit code 0 still means a handled request, including preserved/denied outcomes; it does not mean lifecycle convergence. A scheduled `completed` outcome is not per-allocation retirement evidence. Missing or unknown outcomes use the existing generic failure path. Controller state transitions, authentication, request formats and default local validation are unchanged.
